## Исправления harness и ограничения

- Исправлены уникальные имена topic fixtures и generation sequence для пагинации; collision fixtures не считались runtime-дефектами.
- Verify каналов проверяется по фактическому controller контракту: POST отвечает 201.
- Ошибка DTO limit имеет существующий код BAD_REQUEST; слишком длинный cursor проверяется отдельно от INVALID_CURSOR.
- Mock polling возвращает новый Response на каждый fetch; повторное чтение одного body не считается provider timeout.
- Пустая конфигурация задаётся пустой строкой: ConfigService.set(undefined) может провалиться в validated env/process env.
- Для LATEST_ONLY выполнено ограниченное число reconciliation cycles; требование «ровно один tick» не выдумывалось.
- Смена месяца контролирует Date внутри процесса, не меняя системные часы; ручной retry не объявлен проверенным после отказа предыдущего шага.
- `UNTIL` проверяется на настоящих транзакциях со штатным timeout; он не увеличивался ради зелёного результата.
- Повторная генерация/публикация на mocks не доказывает отсутствие внешнего Telegram-дубля при аварии процесса.
- .tmp содержит только локальные сырые логи. Секреты и настоящие provider payloads в отчёт не включены.
